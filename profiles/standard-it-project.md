# Профиль: IT-проект средней сложности

## Когда использовать

Самостоятельное приложение, сайт, API, настольная программа, учебный IT-проект с несколькими модулями или проект, работа над которым вероятно продолжится в нескольких сеансах.

## Обязательный процесс

1. Изучи структуру, стек, точки входа, существующий функционал и способ запуска.
2. Если возможно, проверь исходную сборку и тесты, чтобы установить начальное состояние.
3. Подготовь план с целями, фазами, критериями завершения, рисками и зависимостями.
4. Согласуй с пользователем план и существенные архитектурные решения до основной реализации.
5. Реализуй по одной фазе за раз.
6. После фазы проверь сборку, тесты и изменённые сценарии; подготовь отчёт и дождись обратной связи пользователя.
7. Исправь замечания в текущей фазе, затем зафиксируй принятый результат согласно Git-процессу.
8. Обновляй план и краткую документацию состояния так, чтобы работу можно было продолжить после перерыва.

## Документация

Используй минимальный комплект, достаточный для продолжения работы: краткий план, инструкции запуска и, при необходимости, описание архитектуры. Журнал решений нужен для решений, последствия которых повлияют на последующие фазы. Не создавай все возможные документы автоматически.

## Завершение

Перед объявлением проекта готовым проверь исходные требования, основные пользовательские сценарии, доступные автоматические проверки, инструкции запуска и известные ограничения. Подключай модули IT-разработки и Git по необходимости.

# Модульный манифест работы ИИ-агентов

Набор инструкций для адаптивной работы ИИ-агентов над задачами разного масштаба: от единичных вычислений до долгосрочных программных проектов.

## Основная идея

Не применять максимальную формальность ко всему подряд. Агент выбирает минимально достаточный процесс по предметной области, объёму и сложности работы, техническим особенностям, рискам и ответственности за результат. Пользователь может в любой момент задать режим или усилить надзор над отдельным аспектом.

## Состав комплекта

- `AGENTS.md` — короткая точка входа. Разместить в корне репозитория или передать агенту вместе с задачей.
- `rules/CORE.md` — общие обязательные правила и порядок работы.
- `profiles/quick-task.md` — единичные и небольшие задачи.
- `profiles/academic-computational.md` — лабораторные, практические, математические, вычислительные и учебные задания.
- `profiles/small-it-task.md` — небольшие локальные изменения в коде.
- `profiles/standard-it-project.md` — проекты средней сложности.
- `profiles/large-critical-project.md` — крупные, долгосрочные, заказные или высокорисковые IT-проекты.
- `profiles/other-multistage-project.md` — многоэтапные задачи вне IT-разработки.
- `modules/it-engineering.md` — инженерные правила для программных проектов.
- `modules/git-and-variants.md` — Git, GitHub, ветки, Lite/Full и другие варианты продукта.
- `modules/accountability-and-risk.md` — как повышать строгость в зависимости от ответственности и последствий ошибки.
- `templates/DEVELOPMENT_PLAN.md` — шаблон плана для проектов, которым он действительно нужен.
- `templates/PHASE_REPORT.md` — шаблон отчёта и контрольной точки фазы.
- `templates/DECISIONS_LOG.md` — необязательный журнал значимых решений.

## Как подключать правила

1. Всегда применять `AGENTS.md` и `rules/CORE.md`.
2. Определить профиль, подходящий текущей задаче. Подключать только один основной профиль; если задача смешанная, сочетать профили выборочно.
3. Для программного кода подключать `modules/it-engineering.md`; для работы с историей или вариантами в Git — `modules/git-and-variants.md`.
4. Подключать `modules/accountability-and-risk.md`, если последствия ошибки, ответственность или особый надзор имеют значение. На практике этот модуль полезен почти всегда, но для тривиальных задач его можно применять кратко.
5. Использовать шаблоны только там, где они уменьшают неоднозначность и помогают продолжить работу. Не создавать файлы документации ради самого факта их наличия.

Не нужно включать весь комплект в контекст для каждой задачи. Если среда агента не загружает дополнительные файлы автоматически, прочитать только выбранные модули или приложить их явно.

## Приоритеты

Явные инструкции пользователя о режиме, оформлении, фокусе внимания и процессе имеют приоритет над автоматическим выбором режима, если не конфликтуют с безопасностью, сохранностью данных и техническими ограничениями. Если пользователь просит особое внимание к конкретной области, агент должен повысить объём проверок и отчётности именно по ней, не усложняя без нужды остальные части работы.
